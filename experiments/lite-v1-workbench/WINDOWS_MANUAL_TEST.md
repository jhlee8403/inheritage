# 회사 Windows Edge 수동 시험 안내

이 통합 시제품의 Windows 실행은 NOT_RUN이다. 기존 C1 단독 HTML의 과거 사용자 확인을 이 파일의 합격으로 취급하지 않는다. 회사 반입·로컬 HTML/Blob worker/WASM 정책을 확인하고 허용된 경우만 시험한다. 정책 제한 시 중단하며 보안 옵션을 완화하지 않는다.

## 전달과 실행 (개발 도구 불필요)

개발 Mac에서 생성 완료된 다음 파일을 허용된 매체로 하나의 폴더에 복사한다.

- `generated/lite-v1.html` — 계산기·PDF.js·OCR worker/core/WASM·한국어 모델을 모두 포함한다.
- `generated/NOTICE.txt` — 재배포 출처·라이선스.
- 이 안내 문서 (`generated/Windows-시험안내.txt`에도 생성된다).
- 가공 시험 표본: 기존 `experiments/offline-ocr/fixtures/text-only.pdf`, `scan-only.pdf`와 새 `generated/fixtures/three-pages.pdf`. 실제 사건자료를 대신 넣지 않는다.

HTML의 기록된 SHA-256/바이트는 개발 보고서·results/build.json과 대조한다. HTML 파일을 Microsoft Edge 창에 끌어 놓거나 연결 프로그램을 Edge로 선택한다. 주소가 file:///...로 시작해야 한다. 인터넷·개발 Mac 서버·Node/npm/Python/Git/Codex 설치가 필요 없다. Mac 폴더 경로를 그대로 만들 필요도 없다.

회사 정책상 허용되는 실제 오프라인 조건에서 다음을 확인하고 날짜, Windows/Edge 버전, 실행한 HTML SHA, 성공/실패·오류 문구를 기록한다. 개발용 자동시험과 사용자 확인을 구분한다. 외부 요청 로그를 수집하지 않았다면 ‘외부 요청 0건 측정’으로 쓰지 않는다.

## 체크리스트

1. 첫 실행: 화면과 품질 경고가 표시되고 추가 다운로드가 없는지.
2. 가공 text-only.pdf 선택: 1/1 표시, 원문 렌더링, 직접 추출 NEEDS_REVIEW 후보.
3. scan-only.pdf 선택: 앞 문서 후보 제거, 직접 추출은 비어 있음, 명시적 ‘현재 페이지 한국어 OCR’ 실행 후 한국어 후보 생성. 이름 누락을 확인하고 원문과 대조하여 후보를 수정. 수정 후보가 계산 입력으로 자동 이동하지 않아야 함.
4. three-pages.pdf 선택: 1~3쪽 이동, 페이지별 후보가 섞이지 않는지. OCR 도중 이동·취소·다른 문서 선택 후 늦은 후보가 덮어쓰지 않는지.
5. C1 세 표본 계산: 배우자+자녀 W=3/7, C1/C2=2/7; 배우자+부모 W=3/7, F/M=2/7; 자녀 3명 각 1/3. 이는 가공 조건의 독립 비교값이며 일반 법률 범위가 아님.
6. Q 수정 즉시 이전 결과 제거와 복사 비활성화, 재계산 후 새로운 분수. 배우자 UNKNOWN은 BLOCKED/미해결 Q, 분모 0은 ERROR이며 이전 성공 결과가 남지 않는지.
7. 최신 결과 복사 후 메모장 붙여넣기. 자동 복사가 제한되면 ‘결과 텍스트 선택’ 후 Edge 복사 메뉴 또는 Ctrl+C. 입력 변경 후 과거 결과 복사 차단. 이미 외부에 붙여넣은 내용은 자동 회수하지 않음.
8. 문서 닫기: 원문·후보 제거. 종료 후 재열기 시 자동으로 이전 사건이 복원되지 않는지. 프로그램은 자동 저장하지 않지만 OS/브라우저의 swap·클립보드·복구 기능까지 안전 삭제한다고 보장하지 않음.
9. 지원 한도 초과/손상 PDF는 ERROR/TIMEOUT으로 중단하는지. 멈춘 경우 PDF/OCR 취소 또는 창 닫기 후 오류 단계/시간을 기록. 장시간 기다리거나 보안을 완화하지 않음.

## 사용 제한

가공 사례 검증 전용이다. 실제 사건 문서·개인정보 사용 금지. 현재 C1은 개시일 2017-01-10 / 기준일 2017-01-11 / BL1-LAW-2016-14409의 승인된 세 유형만 계산한다. R04/R05는 PENDING이며 과거법·입양·상속포기·복수 사건 등은 확대 지원하지 않는다.

한국어 단일 모델의 기존 고정 가공 표본 CER 32.84%와 인명 누락이 확인됐다. 한자·세로쓰기·복잡한 제적등본 정확도 합격이 아니다. 추출/OCR/사용자 수정 모두 NEEDS_REVIEW이며 법률 사실 확정이 아니다.

## 2026-10-25 후속: PDF 초기화 진단판 재시험

사용자 보고: 회사 Windows Edge에서 기존 통합 HTML의 C1 계산은 동작하지만 PDF 영역은 0/0·EMPTY이며 최초 진단도 비어 있었다. Edge 버전·원인·수정본 Windows 결과는 미확인이다. 이 보고는 과거 C1 단독 합격 기록과 구분한다.

1. 수정본 HTML과 NOTICE를 허용된 매체로 다시 전달한다. 예전 파일과 혼동하지 않도록 전달받은 수정본 파일 이름을 별도로 정해 Edge로 연다. 새 화면에는 ‘PDF 초기화’와 ‘C1 초기화’ 상태 줄 및 각각의 초기화 진단 펼침 영역이 있어야 한다.
2. PDF 선택 전에 두 초기화 상태가 READY인지 확인한다. 정상 대기 중에는 PDF 작업 상태 EMPTY/0/0이 맞지만 진단 JSON은 비어 있으면 안 된다. 초기화 전에는 파일 선택이 비활성화되며 PDF 앱 완료 신호 뒤 활성화된다.
3. FAILED/INIT_ERROR/TIMEOUT이면 PDF 초기화 진단을 펼쳐 상태·단계·오류 첫 줄·API 유무·userAgent를 기록한다. READY가 아니면 임의로 PDF/OCR을 계속 시도하지 않는다. 10초 뒤에도 NOT_STARTED/진단 대기 문구가 그대로면 그 문구와 C1 작동 여부를 기록한다. JavaScript 자체가 완전히 막힌 경우 화면의 정적 안내만 남을 수 있다.
4. READY이면 three-pages.pdf를 선택해 1/3 표시·직접 추출·쪽 이동을 확인하고, 가공 스캔 쪽에서만 한국어 OCR을 실행한다. C1 표본 계산도 다시 확인한다.
5. 개발자 콘솔/도구 설치/IE 모드/관리자 권한/보안 완화는 필요 없다. 오류에 포함된 개인 폴더 경로는 공유 전에 지우고, 실제 사건·개인정보를 입력하거나 보내지 않는다. 초기화 진단에서 API가 true인 것은 회사의 Blob worker/WASM 정책 허용이나 실제 Windows 시험 합격을 뜻하지 않는다.

회사의 정확한 원인은 미확정이다. TextDecoder 누락 등의 가공 재현 성공을 회사 PC의 원인 확정으로 취급하지 않는다. 진단판은 누락 API를 임의 구현하거나 PDF.js/모델을 바꾸지 않는다.

## 2026-10-26: Edge 104 호환판 재시험

확인된 회사 버전은 Microsoft Edge 104.0.1293.47, 기준판의 실패는 `PDF_WORKER_CODE / ReferenceError: Iterator is not defined`다. 이번 호환판은 PDF.js main/worker를 공식 **4.2.67 legacy**로 함께 변경했다. 정확한 회사 Windows 실행은 아직 NOT_RUN이며, Mac의 실제 Chromium 104 시험과 구별한다. 회사 Edge 업데이트·추가 설치·관리자 권한·CORS/보안 해제를 요구하지 않는다.

1. 개발 Mac에서 재생성한 `lite-v1.html`, `NOTICE.txt`, 이 안내의 최신 사본을 전달한다. 과거 파일과 구분되는 이름으로 저장하고 Edge에서 직접 연다. `generated/edge104-dev/`의 브라우저·재현 HTML·패키지는 **전달하지 않는다**. 실행에 개발 도구·서버·인터넷은 필요 없다.
2. PDF 선택 전에 C1·PDF 초기화 READY를 확인한다. ‘PDF 초기화 진단’의 `pdfjs`는 `4.2.67 official legacy`여야 한다. Iterator API 값이 false여도 이 버전은 native Iterator가 미리 제공되는 것을 요구하지 않으므로 READY와 실제 처리로 판단한다. API 존재 여부만으로 OCR 성공이라고 기록하지 않는다.
3. 가공 text-only.pdf: 1/1, 원문이 백지가 아닌지, 직접 추출 후보 확인. three-pages.pdf: 1/3~3/3 이동과 문서 교체 시 이전 후보 제거 확인.
4. 가공 scan-only.pdf 또는 3쪽 표본의 스캔 쪽: 원문 글자가 보이는지 먼저 확인하고 한국어 OCR을 누른다. 한국어 후보 생성·직접 수정·취소/이동 후 늦은 결과 차단을 확인한다. 인명 누락·CER32.84% 한계는 그대로다. 백지 원문이나 빈 OCR을 성공으로 기록하지 않는다.
5. C1 세 표본·Q 수정·UNKNOWN BLOCKED·분모0 ERROR·수정 직후 STALE/복사 차단, 최신 결과를 메모장에 붙여넣기 확인.
6. 오류이면 상태·실패 단계·오류 첫 줄·pdfjs 버전·실행한 HTML SHA/파일 크기를 기록한다. 개인정보성 파일 경로는 공유 전에 가린다. 실제 사건자료는 쓰지 않는다.

PDF.js 4.2.67은 Chrome 98+를 대상으로 한 공식 legacy 빌드이고 알려진 CVE-2024-4367 패치 버전이다. 그러나 최신 유지보수 버전이 아니며 모든 취약점/실제 업무 적합성을 보증하는 것은 아니다. 이 시험은 가공 사례 수용시험이며 PDF.js 전체 기능·한자/세로쓰기 정확도·법률 범위 확대 승인이 아니다. 후속 버전 갱신은 별도 검토·회귀 후에만 한다.
