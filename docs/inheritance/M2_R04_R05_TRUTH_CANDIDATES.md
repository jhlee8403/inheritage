# M2 — R04/R05 독립 truth·차단 기대 후보

작성일: 2026-10-23 (Asia/Seoul). 버전 `M2-truth-draft-v1`. **새 규칙·truth·출력 계약 승인: PENDING. M2 엔진 실행: NOT_RUN.** 외부 독립 법률 검토자/검산자 승인: 미실시. 기존 BL1 truth v1 및 M0+M1 승인 기록을 변경하지 않았다. 새 ID는 문서형 후보이며 실행 가능한 fixture가 아니다.

## 1. 공통 입력·상태 계약

법률·U1/U2 대응은 [M2 법률 검토](M2_R04_R05_LEGAL_REVIEW.md) §2~5를 따른다. 아래 수치는 **필요한 규칙·날짜·의존 범위가 모두 승인된다면** 사용할 조건부 기대다. 현재 R04/R05는 PENDING이며 신규 날짜/형식도 현 C1의 지원 범위가 아니므로 정상 결과를 내보내면 안 된다. 이 문서의 수치를 현재 엔진 실행으로 얻었다는 뜻이 아니다.

가공 입력 공통 명세:

- 최초 물건 `SYN-ASSET-01`, 최초 피상속인 `A`, 물건 전체 대비 시작 지분 Q. 0<Q≤1인 정확한 정수 문자열 분수. 사례는 서로 독립적이며 A/B/C/G1/G2는 가공 인물 ID다.
- A→B/C, B→G1/G2는 확인된 성년 친생관계. 시점별 생존·존재·혼인 상태·관계 검토·집합 완전성을 각각 확인한다. 빈 목록·UNKNOWN·누락을 ABSENT_CONFIRMED로 추정하지 않는다.
- 각 해당 시점 A/B 배우자, 추가 자녀·태아·입양·포기·결격/상실·특별수익/기여분·유증/분할/처분·특수재산·외국법·복수 자격·실종 쟁점 등은 없음 확인. 부정 사실이 미확인이면 수치 전제 미충족이다.
- 사건별 법령 후보 `BL1-LAW-2016-14409`. E1=2017-01-10, E2가 있으면2017-01-20. T04의 B 사망2017-01-01은 선사망 근거이며 A 물건을 B에게 전달하는 사건이 아니다.
- 공통 경고는 가공 전용·법정 지분 기초계산·실제 권리 확정 아님·법률 PENDING. reason 문자열과 새 path 구조는 설계 후보이며 현 API에 이미 존재한다고 주장하지 않는다.

**상대분을 구분한다:** 사건의 유입분 대비 상대분, 최초 Q 대비 누적 상대분, 물건 전체분(Q×누적 상대분). E2의 G1은 사건 내1/2이나 최초 Q 대비1/4다. 최종 합계는 말단 취득분과 겹치지 않는 미해결분만 더하며 역사 취득/소비 행을 다시 더하지 않는다.

|상황|현재 게이트 및 안전한 기대|
|---|---|
|사실이 완전한 M2 요청|RULE_PENDING·미지원/날짜/형식 등 필요한 게이트로 차단. 조건부 정답표를 승인 결과로 반환하지 않음|
|필요 사실·법령·의존 승인 불완전|BLOCKED, 최종 allocations/paths 없음, 유효 Q 전부를 미해결 묶음 하나로 보존|
|Q 손상|입력 ERROR, 정상 출력 없음. 잘못된 Q를0으로 만들어 미해결0의 가짜 보존식 금지|

최소 M2는 전체 결과의 원자적 보류를 제안한다. 검증된 E1 역사 기록은 감사 영역에 보존할 수 있지만 BLOCKED의 최종 합계에는 넣지 않는다. 독립 가지 배분+나머지 가지 보류는 ENGINE_DESIGN에 제안돼 있으나 현재 C1 BLOCKED 계약과 달라 별도 승인이 필요하다. 이 문서의 음성 기대는 전체 보류로 통일한다. 수치0 기장은 각 사람의 실체법상 지분0 판정이 아니다.

## 2. BL1-T04 — 한 단계 대습 / BL1-R04

Q=1/1, 기준일2017-01-11. A 배우자 없음, A의 자녀 B/C 전부. B는01-01 선사망, C는 E1 및 기준일 생존. B 배우자는 B 사망 시와 E1에 없음 확인. G1/G2는 B의 자녀 전부이며 E1·기준일 생존. 그 밖의 변동 없음.

X10은 기존 무결성 오류처럼 ERROR로 중단하는 API도 가능하다. 이 문서는 유효Q의 BLOCKED 원장안을 제시하며 최종 상태/오류 분류 승인은 PENDING이다. 어느 선택도 정상 배분으로 보이면 안 된다. 부분 배분 정책·에러 분류·미래 사건 처리와 날짜 계약도 수치와 별개로 승인해야 한다.

## 7. 독립 산술 검산

법적 도출과 별개로 손계산한 뒤 Python3 표준 fractions.Fraction으로 §4 수치8행을 재검산했다. 엔진 함수·fixture·화면 출력에서 정답을 역산하지 않았다. 산술만으로 대습/연속의 법적 경로를 증명할 수 없으므로 §5 비교도 필수다.

- Q=1: 1/2+1/4+1/4=1, 가지/유입1/2=1/4+1/4.
- Q=1/3: 1/6+1/12+1/12=1/3, 가지/유입1/6=1/12+1/12.
- Q=2/5: 1/5+1/10+1/10=2/5, 가지/유입1/5=1/10+1/10.
- MID: Q/2+Q/2=Q, E2 미적용으로 G1/G2 배분 경로 없음.

실제 결과: **산술8 PASS / 0 FAIL, 명령 종료0**. 각 행의 합=Q, 첫 말단=Q/2, 세 말단 사례의 두 가지 내부 값=(Q/2)×1/2와 가지/유입 보존, MID의 두 값=Q/2를 각각 확인했다. 실행은 `python3`의 표준 Fraction만 사용한 일회성 검산이며 제품·법률 선택·R04/R05 실행 코드나 자동 법률 테스트를 작성한 것이 아니다. 재현하려면 §4의 Q와 최종 분수를 문자열 Fraction으로 읽어 위 등식과 대조하면 된다. 숫자 후보에서 변경된 값은 없다. 외부 독립 검산자·법률 검토자 승인은 계속 PENDING이다.

## 8. 현 C1의 구조 변경 후보 — 미구현

1. SINGLE/고정 날짜/직접 path 모델에서 R04의 같은 사건 내 매개 가지와 R05의 별도 사건열을 각각 표현할 새 스키마가 필요하다. 기존 M1 입력을 다른 법률로 조용히 재해석하지 않는다.
