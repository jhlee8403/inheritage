# 축소형 제품 범위 V1

확정 기록일: 2026-10-25 (Asia/Seoul). 근거는 이번 사용자 제품 범위 축소 지시다. 제품 목표 확정과 법률 승인·기능 구현·배포 검증을 구분한다. 이 문서로 기존 승인 기록이나 완료 시험을 소급 변경하지 않는다.

## 제품 목표

**기본 상속분 계산 + 제적등본 PDF 열람/OCR 후보 + 사용자 원문 확인 + Windows Microsoft Edge 오프라인 실행**으로 범위를 축소한다. 아래 PDF/OCR 기능은 제품 목표이며, 현재 모든 항목이 구현/검증 완료됐다는 선언이 아니다.

- 현재 C1 승인 범위의 배우자+자녀, 배우자+부모, 배우자 없는 자녀 균분의 제한 사례.
- 검증된 C1 정확한 기약분수·Q 보존·BLOCKED/ERROR/STALE·결과 복사와 선택 대안.
- PDF 파일 열람/페이지 선택/직접 텍스트 추출, 스캔 PDF의 로컬 OCR 후보 생성.
- 사용자 원문 대조·후보 수정 및 명시적인 사실 확인. 사용자가 확인한 사실을 기존 계산 입력에 명시적으로 반영하는 흐름.
- 인터넷 없는 회사 Windows Edge에서 실행하는 목표. 개발 도구를 사용자 PC에 설치하도록 요구하지 않는 배포 방향.

## 법률 계산의 고정 한계

현재 정상 계산은 **사망 개시일 2017-01-10 / 결과 기준일 2017-01-11 / BL1-LAW-2016-14409**와 기존 `LEGAL_APPROVAL_M0_M1.md`의 조건·제외에 한정한다. 다른 날짜를 같은 법률로 자동 확대하지 않는다. ‘기본 상속분 계산’이 현행 모든 사건 또는 일반 날짜의 계산 지원을 뜻하지 않는다.

법률혼 배우자와 생존 성년 친생자녀/최근친 친생부모 등의 기존 세 유형만 대상으로 한다. 미확인 가족/집합 완전성, 사망 선후 UNKNOWN, 상속포기·입양·복수 상속 사건·미지원 가족관계·규칙/날짜/법령 범위 밖 입력은 기존 게이트에 따라 BLOCKED한다. 손상 Q/구조는 기존 InputError/ERROR 계약을 유지한다. UNKNOWN을 ABSENT_CONFIRMED 또는 CONFIRMED로 바꾸지 않는다.

R04 대습·R05 연속상속, 해당 truth와 새 날짜/의존 승인은 계속 **PENDING**이다. 이 제품에서는 정상 배분 구현을 하지 않는다. 1960년 이후 구법 확장·과거법 자동 선택·1960년 이전/구관습법·복잡한 친족관계 계산도 제품 범위에서 제외한다. 미지원 사실이 있으면 알려진 사람끼리 임의 균분하지 않는다.

## 원문 확인과 개인정보 경계

OCR 후보는 법적 사실 확정이 아니다. 제적등본을 읽었다는 이유만으로 상속인을 자동 결정하지 않는다. 후보/원문 페이지/사용자 수정/명시 확인을 구분해야 한다. 사용자 확인을 향후 기존 계산 입력에 반영하더라도 원본 계산 게이트·날짜·법률 승인을 우회할 수 없다. 이번 기술 실험에서는 OCR과 계산 입력을 연결하지 않는다.

개발·시험·GitHub에는 실제 사건정보/개인정보를 사용하거나 업로드하지 않는다. 완전히 창작한 가공 표본만 쓴다. 자동 사실 확정·클라우드 OCR·온라인 모델 다운로드를 런타임에 추가하지 않는다. 실제 업무 문서 취급·보관/반출 정책은 별도 확인 대상이다.

## 과거 계획과 현재 상태의 구분

기존 DATA_MODEL/ENGINE_DESIGN의 광범위한 과거법·대습·연속 설계는 역사적 검토 자료로 보존하지만 이번 제품의 개발 목표에서 제외한다. 완료된 C1, M2 S0/S1, OCR B1, file PDF 기술 검증 기록은 덮어쓰지 않는다. M2 기술 기반은 보존만 하고 추가 기능을 구현하지 않는다.

C1 단일 HTML의 Windows 1차 수동 확인은 `C1_WINDOWS_MANUAL_ACCEPTANCE_01.md`의 증거 수준에 한정한다. Windows PDF/OCR은 그 시험으로 대체되지 않는다. 기존 file PDF PASS는 고정 가공 PDF 메인 스레드 실험이고, 기존 file worker/model fetch FAIL·스캔 OCR NOT_RUN은 당시 기록 그대로다. 이번 별도 한국어 OCR 실험의 결과는 새 보고서에만 기록한다.

## 이번 작업과 다음 승인 경계

이번에는 고정 가공 스캔 PDF 1쪽·한국어 단일 모델의 file OCR proof-of-concept만 시험한다. 성공해도 한자·세로쓰기·복잡한 제적등본·다중 언어·모든 PDF 해결로 해석하지 않는다. PDF/OCR 대규모 UI 통합·사용자 사실 반영 UI·모델 확대·새 법률/날짜/truth·Windows 실행기/설치 프로그램은 자동 시작하지 않는다.

A안은 보안 완화 없이 worker/WASM/model이 모두 로컬에서 준비되고 후보가 실제 생성돼야 기술 후보로 유지한다. 회사 Windows 정책/실제 오프라인 시험은 별도 필요하다. 실패 시 승인된 독립 실행기+loopback인 B안을 비교할 수 있지만 관리자 정책 허용을 추정하거나 이번에 제작하지 않는다.
