## 실제 개발 작업 환경

관리형 환경은 이번에 `running / connected`, 정책 `restricted / enforced`로 조회되었다. 로컬 `/workspace`는 유효한 대상 Git 체크아웃이 아니며 `/workspace/demo`의 원격은 다른 저장소 `jhlee8403/demo`다. 해당 작업 트리는 변경하지 않았다. 대상 `jhlee8403/inheritage`는 GitHub 연결 도구로 식별·열람했다. Git HTTPS clone은 상속된 proxy:8080 연결 실패로 종료했다. 네트워크 경로·보안 설정을 변경하거나 자격증명을 탐색하지 않았다.

작업 문서 임시 사본은 `/workspace/work/inheritage/docs/inheritance/`에 두고 GitHub 도구로 문서 전용 브랜치의 트리·커밋을 기록하는 방식이다. 이 디렉터리는 Git clone이 아니므로 로컬 `git status`·staging·로컬 커밋 성공이라고 보고하지 않는다. 원격 쓰기 시 기준 main 커밋과 트리에서 파생하고 기존 문서를 변경하지 않는지 검증한다.

개발용 권장 모델은 GPT-6 Astra (`gpt-6-astra`), 추론 강도 xhigh다. **실제 모델 미확인 / 실제 추론 강도 미확인**. 클라이언트는 이 Codex 채팅의 관리형 실행 환경·GitHub 연결 도구로만 식별되며 세부 버전은 미확인이다. 설정 파일 변경·모델 선택 변경은 하지 않았다. 개발 모델을 완성 앱 런타임 의존성으로 삼지 않는다.

## 업무 PC의 확정 요구와 조사 항목

소유자 합의: 업무 PC Edge에서 로컬 실행, 업무 중 인터넷 불필요, 최초 실행에도 OCR 자원 온라인 다운로드 없음. OS·사양·Edge 버전·업무 정책·별도 실행기 허용 여부는 미확인이다.

관리자 조사 항목: OS/아키텍처, CPU·RAM·사용 가능 디스크, Edge 정확한 버전과 업데이트 정책, 로컬 파일·worker·WASM·웹 저장소·클립보드 정책, 실행 파일 반입·서명·loopback 허용, 보안 제품 차단, 이동식 매체·파일 크기 제한. 조사에는 실제 사건자료나 인증정보가 필요하지 않다.

## 배포 대안 — 모두 제안

| 경로 | 사용자 실행 방식 | 장점·확인할 위험 | 결정 조건 |
|---|---|---|---|
| A: 로컬 파일 묶음 | 로컬 HTML을 Edge에서 열기 | 별도 서버 없음. worker/모듈/WASM/모델 로드·file origin 제약을 실제 시험해야 함 | 캐시 없는 Edge 첫 실행과 PDF/OCR 전체 통과 시 검토 |
| B: 허용된 실행기+loopback | 실행기가 같은 PC 전용 주소를 열고 로컬 정적 자원 제공 | worker·자원 경로 관리 가능성. 추가 실행물·서명·포트·정책 허용 필요 | A 실패 또는 정책/운영상 B가 적합하고 관리자·소유자 승인 시 |

단일 HTML 여부는 미정이다. A가 가능하다는 주장이나 B가 반드시 필요하다는 결론 모두 아직 없다. B는 loopback에만 바인딩하고 LAN 기본 공개 금지, 포트 충돌·종료·오류 복구를 설계한다. 업무 PC에 Node.js·Python·npm·개발 도구 설치를 요구하지 않는 배포본을 우선하되 ‘모든 설치가 금지’라는 미합의 제약을 만들지 않는다. 관리자 권한 사용·Edge 보안 비활성화는 대안이 아니다.

## 데이터·자원 수명과 배포 검증

사건자료는 기본 메모리 작업, 명시적 저장/불러오기만 제공한다. worker·모델 캐시와 사건 PDF/OCR/사실관계 저장을 분리한다. 브라우저 캐시·IndexedDB·localStorage·다운로드·로그에 사건이 의도치 않게 남는지 가공 표본으로 확인한다. 사용자가 만든 저장 파일과 클립보드는 앱 종료만으로 지워지지 않을 수 있으므로 자동 삭제를 약속하지 않는다.

원본 동봉·암호화·키 분실 처리·배포 용량·최대 입력 규모는 결정 대기다. 저장 구조는 DATA_MODEL, 성능 표본과 첫 실행 시험은 OCR_EVALUATION_PLAN을 따른다. 출시 전 선택 버전별 manifest·라이선스/고지·해시·무결성 확인, 외부 의존성/외부 요청0, 복사 대안, 훼손 저장 파일 복구 동작을 검증할 계획이다. 이번에는 실행물·모델·의존성을 설치·다운로드·빌드·배포하지 않았다.
