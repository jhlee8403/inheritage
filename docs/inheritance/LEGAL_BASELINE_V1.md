## 1. 제안하는 첫 묶음

## 3. 공통 법령·사실·출력 계약 — BL1-G00

### 3.1 날짜·법령의 경계

첫 truth case의 개시일은 **2017-01-10**, 연속상속의 두 번째 개시일은 **2017-01-20**, 대습 매개인의 선사망일은 **2017-01-01**로 고정한다. 법령 후보 ID는 `BL1-LAW-2016-14409`이며 F-01의 2016.12.20 시행본을 가리킨다. 이는 2017년 전체나 1991년 이후 전 기간의 지원 선언이 아니다.

승인자는 각 사건 날짜에 이 법령 후보를 적용할 수 있는지, 경과조건·후속 개정의 영향이 없는지 확인해야 한다. 다른 날짜·다른 법령은 별도 승인된 매핑 없이는 보류한다. 최신 조문을 과거 사건에 그대로 투사하거나, 법률 공포일을 시행일로 쓰지 않는다. 첫 구현에서는 과거법을 추측하는 자동 연혁 선택기를 만들 필요가 없다. **승인된 날짜/법령 범위만 명시적으로 처리하는 계약**을 먼저 제안한다.

### 3.2 공통으로 확인할 사실

1. 피상속인 ID, 실제 사망일과 선후, 결과 기준일, 해당 인물과 각 관계의 근거가 확인되어 있다. 결과 기준일 이후 사건은 처리하지 않는다.
2. 모든 자녀·배우자 등 **필요한 집합의 완전성**을 확인한다. 후보 명단이 비었다는 사실을 ‘없음 확인’으로 대체하지 않는다. 사람·관계·집합별 `PRESENT / ABSENT_CONFIRMED / UNKNOWN`을 구분한다.
3. 첫 후보의 자녀·부모는 법적 친생관계가 이미 확인된 성년자다. 친자 추정/인지/입양/친양자/친족 효력 충돌을 판정하는 기능은 포함하지 않는다. 배우자는 개시 당시 유효한 법률혼이 확인되고 혼인 무효·취소·이혼·사실혼·재혼 관련 분쟁이 없다.
4. 포기·결격·상실·한정승인 관련 쟁점이 없다는 가공 전제를 사건별로 명시한다. OCR 문구·빈 필드로 이 전제를 만들지 않는다. 관련 사실이 있거나 미확인이면 첫 범위에서 보류한다. 한정승인과 포기를 같은 법적 효과로 취급한다는 뜻은 아니다.
5. 특별수익·기여분·유증·협의분할·특수재산·외국법/국제사법 쟁점이 없는 **법정 지분 기초계산**으로 한정한다. 실제 물건의 상속성·최종 권리귀속·채무 변제책임·송달 적법성은 판단하지 않는다.
6. 모든 사례는 처음부터 만든 가공 인물 ID를 사용한다. 개별 상속인의 자격은 해당 사건에 연결하고 전역 ‘제외자’ 속성을 사용하지 않는다.

### 3.3 예상 상태와 경고

- **현재 실제 적용 상태**: 법률 규칙과 truth가 모두 PENDING이므로, 정상 확정 계산에 사용할 규칙은 없다. 아래 수치는 `승인된다면 기대할 조건부 정답 후보`이며 현재 실행 결과가 아니다. 현재 승인 게이트의 정상 기대는 `BLOCKED: RULE_PENDING`이다.
- 승인 후에도 사실 불완전·법령 범위 불명·미지원 가지면 해당 결과를 `BLOCKED` 또는 승인된 잠정 상태로 둔다. 전체 보류 시 귀속 지분은 0/1, 미해결 지분은 시작 지분 Q다. 이는 누락자의 법률 지분이 0이라는 뜻이 아니다.
- 공통 경고는 `법률 PENDING / 가공 사례 / 법정 지분 기초계산 / 실제 권리 확정 아님 / 적용 법령·전제 확인 필요`다. 미해결 지분을 타인에게 재분배하거나 합계 1로 강제 정규화하지 않는다.
- 사실·관계·기준일·지분·법령이 바뀌면 기존 결과는 STALE로 취급한다. 이 상태 계약도 구현 전 승인 후보다.

BL1-G00의 근거: F-01·F-02·F-07~09와 `ENGINE_DESIGN`의 규칙 선택·보류·재계산, `DATA_MODEL`의 존재/검토 상태. **승인 상태 PENDING**. 확인 질문: 집합 완전성·부정 사실의 확인 책임자는 누구인가? 날짜/법령 범위를 이 정도로 제한해도 되는가? 미승인·미지원 입력을 반드시 보류하는 계약과 경고를 승인하는가?

## 5. 구현 전에 고정한 독립 truth case
