# PDF·OCR 비교 및 오프라인 검증 계획

작성일: 2026-10-18. H §7을 구체화한 설계 제안. 이번에는 공식 문서 일부만 읽었고 설치·모델 다운로드·인식·벤치마크를 수행하지 않았다. 아래 어느 후보도 채택 확정이 아니다.

## 비교할 구성 후보

| 구성 | 모델/문자 후보·계획 | 우선 확인 |
|---|---|---|
| T-A | fast 계열의 한국어·영어/숫자 중심 | 한글 인명·날짜 필드, 렌더링 해상도·속도·용량 |
| T-B | best 계열로 동일 언어·동일 표본 | T-A 대비 수정 비용 감소가 시간·메모리 증가를 정당화하는지 |
| T-C | 필요한 한자·세로쓰기 문자/언어 조합 추가 후보 | 한국어 모델만으로 한자 인명 지원 단정 금지; kor/eng/중문·세로 모델의 실제 존재·지원문자·호환 조합 확인부터 수행 |
| P-A | 공식 SDK가 지원하는 탐지+인식 모델의 CPU/WASM 구성 | 한국어/한자 지원 모델·사전과 ONNX 변환·파일 형식 호환. PP-OCRv5 예제를 시작점으로 삼되 정확한 버전 미정 |

GPU·WebGPU는 선택 비교이며 기본 필수 조건이 아니다. 생성형/VL 모델이나 자체 OCR 학습은 1차 기본 계획에서 제외한다. 높은 일반 벤치마크를 업무 문서 성능으로 환산하지 않는다. 사용할 모델·사전·라이브러리·배포 자원마다 버전, 원주소, 해시, 라이선스, 오프라인 위치, 용량을 기록할 manifest를 단계 B에서 작성할 계획이다.

## 추출·검토 경로

페이지 전체에 텍스트가 존재하는지만 보지 않고 영역별로 유효성·본문 누락·기존 OCR 오류를 판정한다. 직접 추출 우선, 필요한 영역만 OCR한다. 제목은 텍스트이고 본문이 이미지인 PDF, 이미지와 텍스트가 중복된 페이지, 읽기 순서가 깨진 텍스트층을 별도 표본으로 둔다. 추출 원천 ID·영역을 이용해 중복 후보를 식별하되 유사 문자열만으로 자동 삭제하지 않는다.

공통 추출 결과는 문서/쪽 ID, 원본 크기·좌표계, 원문 영역 다각형, 텍스트, 엔진·모델·버전, 인식 점수/미제공, 전처리·회전 변환, 후보/수정 이력을 담는다. 인식 점수는 엔진 간 공통 확률이 아니다. 원문 확대·회전·영역 선택·재인식·수동 입력·인물 병합/분리를 제공하고 이름·일자·관계는 명시적 원문 대조를 거쳐야 한다.

원본은 유지하고 회전·기울기·대비·크기 조정은 별도 전처리본으로 만든다. 인명·날짜를 그럴듯한 값으로 자동 교정하지 않는다. 회전·확대 후 원본 좌표 역변환을 검증한다. 문서 OCR 완료와 가족관계 검토 완료를 다른 진행 상태로 표시한다. 페이지 단위 메모리 해제·취소·실패 페이지 재시도와 전체 입력 규모 제한을 설계한다.

## 가공 표본·측정 제안

실제 사건을 가명화한 표본을 사용하지 않는다. 처음부터 창작한 성명·관계·일자로 제작하고 가공 문서임을 표시한다. 문서 작성자와 정답 확인자가 원문/정답 필드를 서로 대조한다.

초기 제안은 각 군10쪽 이상, 8개 군 총80쪽 이상이다: 한글 인쇄, 숫자/일자 밀집, 한자 혼용, 세로쓰기, 저해상도, 기울기·회전, 수기, 훼손·도장/겹침. 텍스트/스캔/혼합 PDF를 각 군에 가능한 범위로 교차한다. 같은 원본의 해상도 변형을 독립 문서로 과대 계수하지 않는다. 설정 조정용과 고정 평가용 표본을 분리하고 이후 평가용에 맞춰 설정을 다시 조정하면 재평가한다.

| 지표 | 측정 단위·방법 | 합격 기준 제안 |
|---|---|---|
| 인명·일자·관계 필드 | 필드 완전 일치율, 누락·추가·오인 분리. 정규화 전후 별도 | 인쇄체 핵심 필드98% 이상을 초기 검토 목표로 제안; 확정 요구 아님 |
| OCR 텍스트 | 군별 CER, 읽기 순서·줄/영역 누락, 한자와 숫자 오인 별도 | 군별 결과 공개; 전체 평균으로 수기/한자 실패를 숨기지 않음 |
| 사용자 확인 후 사실 | 원문 대조·수정 후 정답과 일치, 미확정은 미확정 유지 | 평가 표본 핵심 사실100% 일치 또는 명시적 보류; 무확인 자동 확정0 |
| 수정 비용 | 페이지/필드당 수정·확인 시간, 클릭·재시도 수 | 업무 사용자가 비교 후 수용 수준 결정 |
| 시간·메모리·용량 | 1/20/100쪽, 최초·반복 실행, 페이지 p50/p95, 최대 메모리, 배포 용량·시작 시간 | 대상 PC 사양 확인 후 상한 결정; 이번 수치 실측 없음 |
| 취소·실패 복구 | 취소 응답시간, 재시도 범위, 메모리 회수, 이미 확인한 사실 보존 | 문서 전체 재처리 강제 없이 실패 페이지 복구 |

98%는 원자료 수치가 아닌 설계 제안이다. 필드 수·분모·표본 난도와 confidence 오확정률을 함께 보고한다. 수기·훼손을 자동 미지원으로 빼지 않고 가능한 인식 수준과 검토 부담을 측정한 뒤 지원 경계를 소유자가 결정한다.

## 오프라인·실행 경로 시험

배포물에 라이브러리·worker·WASM/ONNX·모델·사전·CMap/글꼴 등 선택 구성의 모든 실행 자원을 포함하는 방안을 검토한다. Tesseract의 core 변종과 언어 경로, Paddle의 모델 tar 구성·사전·WASM 자원·module worker 및 버전별 헤더 요구를 목록화한다. 예제의 원격 URL을 복사해 두는 것으로 오프라인 배포를 완성했다고 하지 않는다.

깨끗한 업무 Edge 프로필·빈 캐시·네트워크 차단에서 최초 실행과 반복 실행, 재부팅 후 실행을 시험한다. 외부 요청 ‘성공’뿐 아니라 시도 자체를 관찰한다. file://에서 worker·모듈·모델 로드가 실패하면 관리자 허용을 전제로 loopback 서버/실행기를 별도 비교한다. 보안 해제·확장 프로그램·MCP·개발 도구 설치를 우회 해법으로 삼지 않는다. ENVIRONMENT_PLAN의 정책 결정 전 경로를 확정하지 않는다.
