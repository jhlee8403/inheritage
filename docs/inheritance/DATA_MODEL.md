# 데이터 모델 제안

작성일: 2026-10-18. 분류: 설계 제안 D. 제품 방향은 H §4~8, 법률 개념은 SOURCE_REVIEW U2 대응표를 따른다. 구조·필드명은 구현 확정이 아니며 법률 규칙은 PENDING이다.

## 공통 계약

각 사실은 `값 + 존재 상태 + 검토 상태 + 근거 + 버전`으로 취급한다. 존재 상태는 `PRESENT / ABSENT_CONFIRMED / UNKNOWN`, 검토 상태는 `EXTRACTED / NEEDS_REVIEW / CONFIRMED / CONFLICTED`로 분리한다. 빈 배열·누락 필드를 ‘없음 확인’으로 바꾸지 않는다. ‘모든 자녀·배우자 자료가 확보되었는가’라는 집합 완전성도 개인별 관계 확인과 별도 저장한다.

법률 승인 상태 `PENDING`과 사실 확인 `CONFIRMED`는 다른 축이다. 사용자가 이름·사망일을 확정해도 법률 규칙은 승인되지 않는다.

## 객체와 연결

| 객체 | 식별·주요 필드 | 무결성·사용 |

| Person | 무작위 내부 personId, 원문 성명·별칭, 생존/사망 주장, 검토 상태 | 주민번호 전체 불필요. 이름·생년월일 일치만으로 자동 병합 금지 |
| Relationship | relationId, 양 끝 personId, 친생/일반입양/친양자/혼인 등 유형, 성립·종료일, 효력·근거 | 단순 부/모 문자열로 입양·혼인 이력 덮어쓰기 금지. 관계 주장과 법적 효력 판단 분리 |
| HistoricalFact | 인물/관계, 성별 등 구법상 필요한 속성, 동일가적·이탈원인·호주상속 관련 지위, 유효기간 | 현대 혼인 여부로 출가·가적을 추정하지 않음. 해당 구법이 요구할 때만 추가 확인 |
| DateAssertion | 원문, 일자 종류, 달력·연호, 해석값 또는 최소/최대 범위, 정밀도, 변환 근거 | 사망일/신고일/발급일/실종 사망간주일 구별. 연도만 있으면 월일 null |
| SourceDocument | 문서 내부 ID, 표시명·종류, 파일 해시·쪽수, 재연결 상태 | 사건 PDF는 Git 기록 대상 아님. 파일명만으로 동일성 판단하지 않음 |

| SuccessionEvent | eventId, 해당 피상속인, 개시일 근거, 사건 순서 관계, 적용 규칙 묶음 | 한 사람이 뒤에 사망하면 새 사건. 대습의 피대습인에게 가상 취득 사건을 만들지 않음 |

| RuleVersion | ruleId, 버전, 조건/효과, 공포·시행일, 경과조건, 출처, 승인자·일시·범위·상태 | 출처 버전과 승인 범위를 고정. 승인 전부 PENDING |
| SharePath | 취득자, 최초 지분 대비 상대분수, 물건 전체분수, 사건·자격·규칙열, 각 단계 곱, 유효성 | 같은 최종 인물의 합산 전 경로 중복 제거·자격 충돌 검토 |
| UnresolvedShare | 대상 가지/사건, 보류 이유, 확정 가능한 지분 또는 미상, 의존 후속 경로 | 미상은 0이 아님. 전체 보류 시 시작 지분을 보류 원장에 남김 |
| CalculationSnapshot | input revision, schema/engine/rules 버전, 근거·가정 ID, 결과·검토·보존식, 생성 시각 | 입력 또는 규칙 수정 뒤 즉시 STALE; 옛 결과를 최신으로 복사 금지 |

관계 그래프는 여러 부모·입양·재혼을 표현한다. 가계도는 그 그래프의 특정 시점 보기다. 자기 자신과의 관계·중복 간선·상충 기간·친자 순환은 검증 대상으로 표시하고 자동 삭제하지 않는다. 증거가 충돌하면 검토 상태를 CONFLICTED로 두어 해당 계산을 막는다.

## 분수와 상태

분수는 임의 정밀도 정수의 분자/양의 분모를 사용한다는 설계다. 저장은 `numerator: "1", denominator: "3"` 같은 십진 문자열 쌍으로 하고, 기약화·부호·분모 0·비정상 길이를 검사한다. 0은 0/1, 시작 지분은 0 초과 1 이하를 기본 계약으로 제안한다. 특수 범위를 허용할지는 소유자 결정이다. 표시용 소수는 참고값이며 누적 계산에 재입력하지 않는다.

결과 상태는 `BLOCKED / PROVISIONAL / REVIEW_READY / STALE`로 제안한다. REVIEW_READY는 업무 검토 가능 상태일 뿐 권리귀속 확정이 아니다. 법률 미승인 규칙을 사용하는 개발용 잠정 계산은 가정과 PENDING 경고를 유지하고 일반 확정 결과로 승격하지 않는다.

## 최소 가공 예시

Case C1: 최초 피상속인 P0, 시작 지분 1/3, 기준일 2026-10-18. P0가 2000-06-01 사망, 자녀 P1·P2의 관계는 원문 대조 완료, 배우자 없음은 별도 확인. P1은 2010-06-01 사망하고 배우자 P3만 남았다고 가정한다.

E1에서 P1의 상대 지분 1/2, 전체 지분 1/6을 취득한 뒤 E2에서 P3로 전달하는 경로를 보존한다. P2의 전체 지분 1/6은 E1 경로로 남는다. 이는 TEST_PLAN N-03의 가공 정답 후보이고 PENDING이다. P1이 E1 이전에 사망했다면 E2 전달을 재사용하지 않고 E1의 대습 자격을 새로 검토해야 한다. ‘배우자 없음’이 미확인으로 바뀌면 E1 전체를 보류하고 1/3을 미해결로 보존한다.

## 저장·복원 제안

명시적 저장 파일은 case, schemaVersion, 사실·관계·확인 상태·근거 위치·가정·규칙 참조·revision을 담는다. 계산 결과는 캐시로만 넣고 불러올 때 버전·입력 일치 확인 후 재계산 필요 여부를 표시한다. 원본 PDF 동봉과 암호화는 미정이다. PDF를 동봉하지 않으면 해시/크기/쪽수로 재연결 후보를 비교하고, 불일치하면 근거 미연결로 두며 자동 확정하지 않는다.

불러오기 전에 크기·객체 수·문자열/분수 길이·스키마·참조 ID·관계 순환을 검사한다. 미지원 버전은 읽기 중단 또는 명시적 마이그레이션 안내; 기존 사건을 덮어쓰지 않는다. 문자열은 텍스트로만 렌더링하고 HTML·스크립트 실행 금지. 암호화·키 관리가 결정되기 전에는 ‘안전한 암호화 저장’이라고 표시하지 않는다.
