작성일2026-10-23 (Asia/Seoul). 버전 `M2-test-design-draft-v1`. **시험 설계 확정 PENDING / R04·R05 및 새 truth 법률 승인 PENDING / 구현·실행 NOT_RUN.** 이 문서는 실행 코드·자동시험 fixture가 아니다. 기술 문서 작성 승인과 개발 착수 승인을 구분한다.

[엔진 계약안](M2_ENGINE_CONTRACT.md), [기존 법률 검토](M2_R04_R05_LEGAL_REVIEW.md), [문서형 정답 후보](M2_R04_R05_TRUTH_CANDIDATES.md), LEGAL_APPROVAL_M0_M1 및 실제 C1 코드·시험·수동 검증 화면 계약을 대조했다. 이번 변경은 두 설계 문서뿐이며 기존 M2 후보·Q-09·M1 승인 기록은 고치지 않는다.

## 1. 정답 출처·독립성·실행 단계

법률상 수치/경로의 출처는 기존 문서형 T04/T05/T05-B와 그 Q/기준일 변형이다. 새 가족관계의 법률 정답을 만들지 않는다. 구현 결과를 보고 기대값을 수정하지 않으며 동일 엔진 함수로 기대값을 계산하지 않는다. 기대값을 변경해야 한다면 원 후보·근거·변경 사유·검토/승인 이력을 별도 남긴다. 여기서는 바꾸지 않았다.

정상 후보 입력·중간값·말단·경로를 문서에서 고정하고 독립 검토한 뒤 자동화할 계획이다. 수치 기대는 literal 분자/분모 문자열, 사람·사건·매개·유입 참조도 독립 literal 구조로 작성한다. 비교할 때 public API의 분수 정규화/곱셈/합산으로 정답을 만들지 않는다. 산술 불변식 검사와 고정 truth 비교를 둘 다 수행한다. 임의 정수 기반 산술 property 검사는 법률 자격 승인과 분리한다.

|시험 층|향후 방법|현재|
|---|---|---|
|문서 정합성|링크·JSON 문법·ID·기존 수치와 의미 대조|이번에 문서 검사만 수행. M2 엔진 합격 수치로 세지 않음|
|순수 구조/분수/무결성|법률 선택 없이 조립한 명시적 원장에 검증기 적용|미실시, 코딩 미승인|
|PENDING 게이트|새 모듈 요청에서 정상 결과 없음, Q 전체 보류|시험 설계만. 기존 C1의 게이트와 M2의 새 형식 구별|
|조건부 양성|별도 승인 이후 검토된 바인딩으로 문서 truth를 비교|현재 실행/활성화 금지|
|브라우저/화면|공개 M2 API·async/hash 및 별도 승인된 UI 연결 시험|미실시. 현재 M1 화면은 수정하지 않음|

나중의 양성 테스트용 승인 컨텍스트는 검토된 명시적 범위를 가진 별도 test fixture여야 한다. 한 사건 JSON에 approved=true를 넣거나 기존 레지스트리를 전역 수정해 다른 시험이 통과하게 만들면 안 된다. R04/R05 allowlist·날짜 승인 절차를 테스트 helper가 우회해서도 안 된다. 현재는 그런 fixture를 작성하지 않는다.

## 5. InputError 분류와 기존 후보와의 차이

다음은 최종 승인 전 분류 제안이다. M2-X10의 기존 문서형 후보는 유효Q 전체BLOCKED안과 ERROR 대안을 모두 열어두었다. 계약안은 C1 무결성 오류와의 일관성을 위해 **중복/순환/실질 이중소비 InputError**를 우선 제안한다. 이 문서가 X10 정답을 수정/확정한 것은 아니다. 분류 선택을 기술 검토에서 기록한 뒤 자동시험의 단일 기대 상태를 고정해야 한다. ‘BLOCKED 또는ERROR 아무거나 통과’ 같은 느슨한 assertion으로 구현 결함을 숨기지 않는다.

|시험 ID|입력/오염|고정할 제안·검증|
|---|---|---|
|M2-E01|X16의손상 Q·분모0·음수·0·1초과·정수 아닌값·길이초과|InputError, 결과 없음. 현재 fraction.mjs code/field별 기대 보존. denominator0은fraction.denominator 등 실제 C1 계약과 구별 없이 추측하지 않음|
|M2-E02|중복ID·빠진 명시참조·자기참조·관계/사건순환|InputError 권고. 사실 집합 미확인을MISSING_REFERENCE로 성급히 던지는 결함은 G03으로 별도 검출|
|M2-E03|다른ID의동일source 이중소비·asset/owner 불일치|InputError 권고, 정상원장/부분배분/미해결0 반환 금지. Q-09의 분류 확정 대기|
|M2-E04|결과 생성 후 말단합·path참조·소비잔액·rule/proof 오염|RESULT_INTEGRITY_ERROR, 외부 게시/복사 안 함. 사용자 사실 부족BLOCKED와 내부 결과 결함 구별|
|M2-E05|JSON 아닌의존값·WebCrypto없음/거절|SnapshotError 명시. 상수hash/약한hash/온라인계산 fallback 금지|
|M2-E06|길이1024인유효Q의 내부 연산 분모가 더 길어짐|정확한 내부 분수 운반·보존검사·JSON표시, 외부Number변환 금지. 출력사본 외부재입력은 기존길이제한대로 거부|
|M2-E07|지원하지 않는schema/버전,C1snapshot을M2refresh로 또는그 반대|명시적인 버전/형식 오류, 자동해석/캐시승격/원본덮어쓰기 금지|

UI의 ERROR 표시는 법률 정답 상태가 아니며 InputError 후 직전 성공 결과가 남아서는 안 된다. 유효 Q의 BLOCKED에는 미해결 Q가 있지만 무효 Q의 InputError에는 그런 원장을 만들지 않는다. 자원 한계의 정확한 byte/건수 값은 아직 미정이다. 한계값을 정한 뒤 경계±1 및 중단 시간/메모리 검사를 추가하며, 이번 문서에서 실측 수치를 만들지 않는다.

## 6. STALE·hash·비동기 시험 계획

### 10.3 구조 오류·미완료 사실의 분리 — G03~05·09, E01~04/07

F1/F2 레코드를 실제로 두고 review/complete/가족 내용만 미완료로 만든 입력은 BLOCKED와 유효Q 전체 미해결을 기대한다. F1/F2를 명시 참조하면서 실제 테이블에서 제거한 입력은 BROKEN_REFERENCE InputError를 기대한다. 계약 §3의 설명용 입력 골격(eventFacts=[])은 후자이며 정상 fixture가 아니다. 불완전 사실 시험을 그 골격으로 대신하지 않는다.

중복 ID·깨진 관계/사건 참조·명백한 구조 순환·실질 이중 소비는 InputError를 기술 우선안으로 삼는다. M2-X10의 기존 BLOCKED 후보와의 차이를 승인 전 기록으로 유지한다. 향후 분류를 고정한 뒤 code/field 하나를 assertion하고 `BLOCKED || ERROR` 또는 예외가 나면 무조건 통과하는 시험은 금지한다. 적용 가능한 Q 검사/구조 검사/승인 게이트의 도달 여부도 각각 확인한다.

E01/02/07에는 자원 프로파일의 인물256·관계512·사건32·JSON1MiB 등 각각 한계-1/한계/한계+1 변형을 붙인다. 한계 안에서 법률 성공을 기대하지 않고 기술 수용 또는 다음 PENDING 게이트 도달만 비교한다. JSON bytes는 UTF-8로 계산하고 멀티바이트 문자열도 사용한다. 1024자 외부 분수는 별도 경계로 유지한다. 상한 초과는 INPUT_LIMIT_EXCEEDED, 미지원 필드는 UNSUPPORTED_INPUT_FIELD, schema 불일치는 명시적 버전 오류를 권고한다.

원시 JSON에 같은 키를 root/중첩 객체에 두 번 넣은 경우 strict 파서가 덮어쓰기 전에 DUPLICATE_JSON_KEY로 거부하는지 검사한다. 이미 JSON.parse한 객체만 가지고 원시 중복 키 검사를 통과했다고 하지 않는다. 비JSON 객체·접근자·객체 자체 순환, 허용되지 않은 필드와 속성 조작 표지도 별도로 검사한다. 파서·객체 API의 최종 오류명은 구현 전 기술 검토로 고정하며 이번에는 미구현이다.

### 10.4 중복 소비·같은 숫자와 다른 경로 — L01~12

- L06/09: 서로 다른 targetEventId/pathId라도 동일 root asset·동일 선행 취득을 재소비하는 입력을 만든다. ID 중복 검사만으로 통과하지 않게 한다. source 취득자와 후속 피상속인·물건·순서가 맞는지 각각 검사한다. 명백한 이중 소비에는 단일 InputError 기대를 고정하고, 중복 행을 조용히 제거/합산해 성공시키지 않는다.
- L04/05/07: R04 가지 기준B를 실제 취득에 넣거나, R05 역사B를 최종 말단과 함께 합산하거나, 소비된 B를 말단으로 남긴 원장을 각각 오염시킨다. 원장 무결성 검사는 이런 기술 입력에 대해 법률 배분을 새로 계산할 필요가 없다. 합계 검사와 별개로 기준/역사/소비/말단 역할 참조가 실패하는지도 비교한다.
- L01~03: T04/T05의 동일 최종 분수는 필요한 조건일 뿐 충분하지 않다. 별도 승인 후 실제 출력에서는 T04의 E1·B매개·B 실제취득 없음, T05의 E1 B 실제취득·E2 유입/소비·G1/G2 취득을 각각 비교한다. 서로의 path를 교체하면 숫자가 같아도 실패다. 현재는 원 후보를 옮긴 구조 검토용 레코드의 차이만 검사 대상으로 설계하고 정상 계산을 수행하지 않는다.
- L10/11/12: ID를 일관되게 바꾸거나 순서를 뒤집어도 의미상 사람/경로 기대는 유지한다. 분수 필드의 단위·rule/law/승인 참조를 오염시킨 결과는 합계가 맞아도 실패해야 한다. 서로 다른 사람 ID가 현실의 동일인인지 자동 추정하는 기능은 없다.

### 10.5 미래 사건·기준일·옛 결과 복사 — P07~08, G01/06/13/14, S01~09

정확한 CONFIRMED DAY 사실로 E1≤기준일<E2인 경우와, YEAR/UNKNOWN·같은 날짜·상충 날짜인 경우를 구분한다. 후자는 미래로 추정하지 않고 전체 BLOCKED다. 미래 E2의 가족만 미완료이고 E1·기준일 이전 관련 사실과 무관한 경우에만 NOT_YET_OPENED **후보**를 비교한다. 공유 관계/생존/유입 출처가 E1에도 영향을 주면 전체 BLOCKED다.

현재01-15/21 기준일과 R05/E2 의존 승인은 PENDING이다. 따라서 지금은 이 날짜 요청에 정상 B/C 말단 수치가 나와서는 안 된다. P07/08의 정상 수치는 별도 승인 후, 원 후보 그대로만 시험한다. NOT_YET_OPENED 분류 후보만으로 E2의 배분/소비/취득을 생성하지 않는다.

S01/02는 revision을 올리지 않은 기준일·사건열·Q·법령/승인 변경도 hash 의존 변화와 즉시 STALE를 유발하는지 검사한다. S07/08은 변경 event와 같은 동기 구간에서 최신 결과 영역이 비워지고 선택/복사가 막히는지 확인하며 hash 완료를 기다리지 않는다. 계산A를 보류한 뒤 변경/계산B를 완료시키고 A의 늦은 성공·실패·복사 완료·취소 후 완료를 전달해 B나 STALE 상태를 덮어쓰지 않는지 검사한다.

S09의 과거 E1 감사 기록도 현재 hash/proof와 분리해 보관하면 STALE_HISTORY다. 최신 최종 결과처럼 복사하면 실패다. 과거 결과를 외부에 이미 복사한 clipboard까지 지운다고 시험하거나 약속하지 않는다. 순수 최신성 검사는 가공 기술값/BLOCKED 결과로 설계할 수 있으며 정상 상속 수치가 반드시 필요하지 않다.

이 보완은 시험 설계뿐이다. 기존51개 항목·기존 C1 기대값·원 M2 truth·법률 승인 기록은 보존하며, 코드·브라우저 시험·성능 측정·개발 착수를 이번 작업에서 수행하지 않는다.

이번 문서 점검에서는 기준 커밋의 두 문서 본문이 그대로 유지되고 추가 절만 붙었음을 비교했다. 기존51개 ID/행의 순서·중복 여부, JSON 예시6개의 문법, 상대 링크, diff 공백 검사를 확인했다. 문서 검사 명령은 종료0이며 M2 엔진·자동시험·브라우저 통과 건수로 보고하지 않는다.
